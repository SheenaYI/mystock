# 量化研究设计 v0.2

## 1. 目的与命名

本文是 `mystock` 的研究合同。此前讨论中出现的 `1A`、`2A` 只是工作代号，
**不是按先后顺序排列的实验**：

- **技术基线能力**是第一个可执行能力；
- **状态条件化的动态因子选择能力**是当前研究主线；`2A` 仅保留为历史别名；
- 基本面、事件/新闻、组合风险与实时交易是后续扩展，而不是完成当前主实验的前提。

本研究要检验的是：在固定技术因子基线之上，一个受约束、以证据为依据的动态因子
配方，是否能带来改进。它不等于策略已可自动实盘交易。

## 2. 边界与当前证据标准

### 2.1 首个研究股票池

首个研究股票池为**沪深 300 的历史成分股**。每个决策日只允许该日实际属于成分股的
股票进入候选池，不能把今天的成分股名单倒灌到历史日期。

### 2.2 信息边界

在决策日 `t` 收盘时，流程只能使用该时点已经可见的信息；订单在下一交易日 `t+1`
的**未复权开盘价**成交。因子值、成分股名单、数据源版本及其可用日期必须写入每次
运行的清单（manifest）。

当前标准是**研究级 / 相对 PIT**，不是完全严格 PIT。OHLCV 与历史成分股可以控制，
但公司行动、基本面与新闻的完整“实际可得时间”历史尚未端到端闭合。报告必须标出这
一限制；在数据源和可得时间戳均被证明前，任何结果都不得称为“完全严格 PIT”。

当前正式研究输入改为 `data/raw/unadjusted_akshare/`：由 AKShare `adjust=""` 重新抓取，
包含未复权 OHLCV 与 `amount`，并绑定文件哈希 manifest。旧的 `data/raw/daily/` 保留为
探索归档，**不能**作为正式回测的下一开盘成交价。正式运行必须同时具备未复权 OHLCV 清单、
历史成分股清单与公司行动证据；缺任一项即显式停止。前复权历史只可用于人工探索，
不进入本协议的正式结果。

### 2.3 数据与系统演进

系统为未来的如下流程预留接口；当前真正执行的范围是中间的研究链条。

```text
历史数据 / 实时数据
        |
        v
分析：因子 -> 预测 -> 回测 -> 报告
        |
        v
组合与风险控制（后续扩展）
        |
        v
人工确认后的交易执行（未来）
```

历史与实时数据共用同一数据合同：证券代码、市场日期、`available_at`、数据源和内容
哈希。将来的实时接口只能作为适配器，不能改变研究合同，也不能悄悄改变历史回放。

## 3. 研究时钟

### 冻结的大时间切分

| 阶段 | 时间 | 允许做什么 | 禁止做什么 |
| --- | --- | --- | --- |
| 开发 / 训练 | 2021-01-01 至 2023-12-31 | 三折证据、LightGBM M1–M6 选择、因子卡与状态规则开发 | 查看 2024/2025 策略绩效后调优 |
| 验证 | 2024-01-01 至 2024-12-31 | 对冻结后的 S0–S3 做一次样本外比较 | 根据结果重选因子、超参数、成本或状态阈值 |
| 锁定测试 | 2025-01-01 至 2025-12-31 | 在前两段完全冻结后运行一次最终检查 | 任何基于 2025 结果的再优化 |

S0–S3 的原始对照合同刻意让三个时钟对齐：

| 项目 | 初始冻结值 | 含义 |
| --- | ---: | --- |
| 预测期限 `H` | 20 个交易日 | 标签：从下一交易日开盘持有至下一次调仓开盘的相对收益。 |
| 调仓频率 `R` | 20 个交易日 | 组合每月重新审视一次。 |
| 配方/模型频率 `K` | 20 个交易日 | 市场状态、因子配方与模型每月重新审视一次。 |
| 组合 | TopK = 10，n_drop = 5 | 最多持有十只；调仓时最多替换五只当前最弱或已不合格的持仓。 |

这套 20 日时钟仍是 S0–S3 的可复现对照基线。S4-W1 是后续的探索性挑战者，另行使用
`H=5, R=5, K=20, J=20`：每日更新技术因子，预测未来 5 个交易日、每周调仓；LightGBM
每 20 个交易日重训、LLM 每 20 个交易日重新从固定七因子作一次独立配方决策。两套合同
不能混为同一个严格控制变量实验；S4 首先回答的是“整体方向是否值得继续”，之后才做归因。

原始 20 日合同中，每个决策日 `t` 的流程：

```text
t 收盘时可见的信息
  -> 构建因子面板与市场状态快照
  -> 选择合法的因子配方
  -> 仅用在 t 前已成熟标签训练 LightGBM
  -> 对合格沪深 300 股票打分
  -> 用 TopK / n_drop 形成目标组合
  -> 在 t+1 开盘成交
  -> 持有至下一次 20 日决策
```

对历史决策日 `s`，标签定义为 `open(s+21) / open(s+1) - 1`，并减去同期沪深 300
的同口径收益。它模拟在 `s+1` 开盘买入、持有二十个交易日、在 `s+21` 开盘进入下一
轮调仓的可交易收益。因而在 `t` 收盘训练时，只能使用 `s <= t-21` 的样本；该退出
开盘价已经真实发生。每次月度重训均使用此前所有已成熟样本，最新成熟标签在下一轮加入。

### 3.1 成熟标签、内部验证与点时训练

“**已经成熟的历史标签**”不是指样本很旧，而是指它对应的未来持有期已经在当时真实
结束、收益答案已经存在。对历史决策日 `s`：在 `s` 收盘计算因子，`s+1` 开盘进入，
`s+21` 开盘退出；只有退出开盘已经发生后，这条样本才可拿来训练。

例如今天是决策日 `T`，模型预测二十个交易日：

```text
更早的成熟样本             最近 60 个成熟交易日             T 收盘
训练 LightGBM              内部验证 / early stopping       产生新预测
|-------------------------|-------------------------------|---------->
                                                    仅允许 s <= T-21
```

最近 60 个成熟交易日只用于内部验证，即让 LightGBM 判断继续增加树是否已经开始只贴合
旧噪音；它不用于训练停止以外的策略绩效结论，更不是 2024 验证期或 2025 锁定窗。更早的
成熟样本用于拟合模型。然后模型只读取 `T` 日可见的七因子，为 `T` 日合格股票分别产生
预测分数；TopK/n_drop 将分数变成目标组合，订单留到 `T+1` 开盘。

```text
T 收盘：历史成员股 + PIT 因子 → 仅成熟标签训练 → Qlib LightGBM → 当日股票分数
T+1 开盘：按未复权开盘价成交
T+1 收盘：按未复权收盘价估值净值
T+20 收盘：下一次决策；此前新增成熟的旧样本可加入训练
```

这是一种扩展训练窗口：每二十日重新训练一次，但不改变过去标签，也不提前使用还没有
走完二十日持有期的结果。当前代码已经接通“七因子 → 成熟标签 → 滚动 Qlib → TopK/n_drop”
的程序路径；但公司行动证据尚未生成正式 PIT 因子价格、正式数据档案未齐，因此不能据此
产生正式绩效结论。

每个开发折还必须保留两种非训练缓冲：因子计算向前加载至少 120 个交易日的行情预热期；
评估期最后一次决策后再读取二十个交易日，以兑现其标签。它们不是机械地删除每年头尾
二十个交易日。

`return_60` 与该时钟不冲突：它只是在 `t` 用过去 60 个交易日构造特征，不会改变
20 日预测期或 20 日调仓期。

## 4. 模型与回测分别做什么

```text
过去的 OHLCV + 历史成分股
  -> 每只合格股票的因子向量
  -> LightGBM 输出横截面预测分数
  -> 对分数排序
  -> TopK/n_drop 把排序转成目标持仓
  -> 次日开盘执行、计入成本、持仓与净值
```

LightGBM 是监督学习的预测/排序模型：它从已可见的历史样本中学习“过去因子值”与
“未来 20 日标签”的关系，为每只股票给出可比较的分数。它不直接决定买卖数量或卖出
规则；组合层负责把分数变成持仓目标，执行账本把目标持仓变成历史模拟。

## 5. 因子路线图

最终的特征面板会合并三类信息，但它们将逐层引入，这样每次改善才知道来自哪里。

```text
OHLCV ----------------------> 技术因子
财务报表 -------------------> 基本面因子
新闻 / 公告 ----------------> 事件因子
                                  |
                                  v
                      同一日期 × 股票的特征面板
                                  |
                                  v
                           LightGBM 股票分数
```

### 5.1 当前：五类技术因子菜单

技术因子菜单暂定为 **25 个**：S0 的七因子初始基线、原有 13 个技术扩展，以及 5 个
相对市场扩展。S1/S2/S3 从七因子初始配方出发，可在全部已注册因子内
add/drop/replace，但每次实际配方只能有 5–9 个因子。25 个是候选菜单上限，不代表每次
模型都使用 25 个因子。

对 S3 而言，“从七因子出发”是每个 20 个交易日决策的独立起点：系统不会把
上一个调仓日的扩展配方自动继承为下一期基线。LLM 在每个决策日重新面对固定七因子；
`abstain` 表示本期保持这七因子，不表示沿用上一期扩展配方。

| 家族 | 初始基线 | 扩展候选 |
| --- | --- | --- |
| 趋势/动量 | `return_5`、`return_20`、`return_60`、`ma_gap_20` | `return_120`、`trend_efficiency_60`、`vol_adjusted_return_60` |
| 价格形态/反转 | — | `return_1`、`reversal_5`、`ma_gap_5`、`high_low_position_60`、`return_skewness_20` |
| 风险/波动 | `volatility_20`、`intraday_range` | `downside_volatility_20`、`drawdown_60` |
| 成交量/流动性 | `volume_ratio_20` | `volume_trend_20`、`volume_price_corr_20`、`illiquidity_20` |
| 相对市场 | — | `beta_60`、`market_corr_60`、`idiosyncratic_return_20`、`idiosyncratic_return_60`、`residual_volatility_60` |

公式口径冻结如下：`return_n = close[t]/close[t-n]-1`；`ma_gap_n = close[t]/mean(close[t-n+1:t])-1`；
`volatility_n` 是过去 n 日收益标准差；`volume_ratio_20 = volume[t]/mean(volume[t-19:t])-1`；
`intraday_range=(high[t]-low[t])/close[t]`；`reversal_5=-return_5`；
`downside_volatility_20` 是二十日负收益的标准差；`drawdown_60=close[t]/max(close[t-59:t])-1`；
`volume_trend_20=mean(volume[t-4:t])/mean(volume[t-19:t])-1`；
`volume_price_corr_20` 是二十日收益与成交量变化的 Pearson 相关；`illiquidity_20` 是二十日
`abs(return)/amount` 的均值；`trend_efficiency_60=abs(return_60)/sum(abs(daily_return),60)`；
`vol_adjusted_return_60=return_60/volatility_60`；`high_low_position_60` 是收盘价在六十日高低区间
中的位置；`return_skewness_20` 是二十日收益偏度。所有除零和不足窗口情形都显式标记为缺失，
不使用补值。

相对市场因子使用沪深300收盘序列：`beta_60` 是过去60日个股收益对指数收益的滚动 Beta；
`market_corr_60` 是滚动相关系数；`idiosyncratic_return_n` 是个股 n 日收益减去滚动 Beta
乘以指数 n 日收益；`residual_volatility_60` 是市场暴露剔除后的60日收益波动率。简单的
“个股收益减指数收益”或“个股波动率除指数波动率”没有单独注册，因为它们只对当日横截面做
共同平移/缩放，已被审计为与原因子高度重复。行业相对强弱暂不注册，待历史行业分类档案接入。

候选池追求的是**高覆盖**，不假设 25 个因子天然低相关；真正被选择的配方必须稀疏、低冗余。

本轮重建后的确定性筛选门槛冻结为：

- 预热期不计入覆盖率；从因子首次形成正常横截面后计算。中位覆盖率至少 95%，且至少
  95% 的非预热交易日达到 95% 横截面覆盖；
- 强相关仍定义为绝对日度横截面 Spearman 中位相关不低于 0.80，每个新增强相关簇最多选一个；
- 历史 RankIC 只作为方向和稳定性证据：三折中至少两折方向一致，且至少两折的绝对平均
  RankIC 不低于 0.01。正负方向都可以，不能把负 RankIC 误判为无效；
- 状态条件证据少于 20 个成熟交易日时标记为不足，不得支持 add/replace；
- 最终仍需通过组合级边际证据门槛，不能仅凭单因子 RankIC 放行。

本轮审计输出位于 `data/warehouse/factor_library_rebuild/`：覆盖率、相关矩阵、相关簇和
三折/状态 RankIC 证据分别保存为 CSV/JSON，作为下一版 S3 Prompt 的输入，而不是直接把
审计结果当成最终收益结论。

初版相关性规则：

- 每日计算沪深 300 横截面的 Spearman 秩相关；
- 在每个开发折中以中位相关系数汇总因子对；
- 若三折中至少两折的绝对中位相关系数不低于 `0.80`，定义为强相关簇；
- 动态配方每个强相关簇最多选一个因子；只有预先声明的例外、并且在至少两折有正向证据
  时才可突破。

### 5.2 后续：基本面因子

基本面将成为确定性的低频因子，例如 `log_mcap`、`bp`、`roe_ttm` 与 `asset_growth`。
它们与 Fama-French 中的规模、价值、盈利能力与投资维度的经济含义有关，但并不是对
Fama-French 因子模型的机械复制。每个数值都必须带有真实的披露/可得日期，才能加入
每日因子面板；后来的财报修订不得改写历史决策。

### 5.3 后续：事件/新闻因子

LLM 可以从已归档的新闻或公告中抽取结构化字段；确定性代码再将它们聚合成可复算的
1/3/5 日因子，例如意外程度、相关性、方向、置信度与衰减。历史月度决策不能浏览新的
网页结果，否则会破坏信息边界。

## 6. 主研究问题：动态因子配方

动态方法不是让 LLM 任意发明因子，而是检验：在一个冻结菜单中，结合市场状态、受到
证据约束的因子配方选择，能否优于固定技术基线。

### 6.1 市场状态快照

任何 LLM 调用之前，系统先确定性计算状态快照：

- 沪深 300 的 20 日、60 日收益；
- 20 日波动率；
- 相对过去 60 日高点的回撤；
- 合格股票中位于 20 日均线上方的比例；
- 股票横截面收益离散度；
- 个股过去 20 日收益的两两相关性中位数。

状态阈值只使用 2021 年上半年校准一次，随后冻结：若二十日波动率高于校准样本的 80%
分位，或六十日回撤低于其 20% 分位，优先判为 `high_risk`（高风险）；否则若六十日指数
收益为正且成分股站上 MA20 的比例高于校准中位数，判为 `trend`（趋势）；其余为
`range_or_uncertain`（震荡或不确定）。市场状态给 LLM 提供上下文，但不以硬规则直接
决定因子配方。

S3 的固定调用顺序为：

```text
确定性市场指标
    → 代码生成 S1_trend / S2_stress / S3_range_or_uncertain 状态
    → 读取截至决策日已成熟的 RankIC、ICIR、状态证据、相关簇和组合边际证据
    → ReAct-lite observe → assess → decide
    → 固定七因子起点上的合法配方
    → LightGBM 仅使用已成熟标签训练并输出股票分数
```

LLM 不负责判断原始市场指标，也不直接训练模型；它只在确定性状态和历史证据已经生成后，
从注册因子菜单中选择合法配方。

### 6.2 ReAct-lite 决策合同

### 6.1.1 决策日前历史因子证据构造规范

“因子证据”不是让 LLM 直接读取未来收益，而是由确定性代码在每个决策日 `t` 先生成一份
可回放快照。快照只使用 `t-21` 及更早已经成熟的 20 日标签；尚未走完持有期的样本不进入
任何统计量。每个候选因子至少记录：

- 全部成熟日期的横截面 RankIC 均值、中位数、观测数和 ICIR（均值 / 标准差）；
- 当前决策日横截面覆盖率；
- 按当日市场状态分组的 RankIC、ICIR 和观测数；状态样本少于 20 个成熟交易日时标记
  `insufficient_evidence`，不能被当作正向支持；
- 在成熟日期内计算的横截面 Spearman 相关性簇，默认绝对相关系数阈值为 0.80。

证据快照同时保存 `as_of`、`mature_through`、状态分类、相关性阈值和证据状态，并对完整
输入做哈希后写入 ReAct-lite 调用日志。LLM 只读取这份快照，不能读取原始未来标签、2024
验证结果或 2025 锁定结果。证据的作用是让 LLM 比较“当前状态下是否有历史支持、是否重复、
是否覆盖不足”，而不是替代 LightGBM 进行数值预测。

实现入口为 `src/research/llm/evidence.py`；它不参与 S0/S1/S2 的因子配方，只在 S3 的
决策前生成快照。

如果成熟样本不足、状态证据不足或因子之间存在无法消解的矛盾，合法输出是 `abstain`；
系统不得用验证期或锁定窗表现补齐证据。

新增一条确定性组合门槛：如果没有明确的组合级边际证据，系统默认 `abstain`。候选因子
只有同时满足以下条件，才会进入允许 `add` 或 `replace` 的菜单：

1. 因子证据在历史开发折中稳定；
2. 相对固定七因子组合，至少两个历史折显示组合边际改善；
3. 换手、回撤和 Beta 没有显著恶化。

单因子 RankIC/ICIR 为正，或只改善单因子统计量但没有组合改善，均不足以执行新增或替换。
该门槛由确定性代码先执行；证据字段缺失时 fail-closed，LLM 不能通过提示词绕过它。当前实现
在每个开发折分别训练“七因子”和“七因子 + 候选因子”的同一 LightGBM，再按相同 TopK 规则比较
收益、Sharpe、最大回撤、换手和 Beta 差异；它是 LLM 放行动作的筛选证据，不替代最终执行账本
回测。正式结果仍以统一回测链路为准。

#### 6.2.1 组合边际证据计算器：目的与原理

它回答的问题不是“这个因子的 RankIC 是否为正”，而是：

> 在相同的股票池、标签、TopK 规则和历史时段下，把候选因子加入固定七因子后，实际形成的
> 组合是否有可重复的增量？

对每个决策日 `t` 和候选因子 `c`，确定性代码分别构造两条历史组合：

```text
基线组合：固定 7 因子 → 横截面打分 → TopK=10
候选组合：固定 7 因子 + c → 横截面打分 → TopK=10
```

两条组合必须使用相同的历史日期、股票池、标签、缺失数据规则和成本/交易约束。然后在开发期
折 F1、F2、F3 中分别计算：

- 组合累计收益和 Sharpe；
- 最大回撤；
- 调仓换手代理；
- 相对基准 Beta；
- 候选组合减去基线组合的差值。

候选边际证据现在使用与主链路相同的 Qlib/LightGBM 配置，在 F1/F2/F3 开发折分别训练
“基线配方”和“基线+候选因子”模型，再比较两者的 TopK 预测组合。它仍不是正式的
整数手执行账本，但不再把等权因子排名代理当成 LightGBM 改善证据。

候选因子的放行逻辑为：

```text
factor_evidence_stable = true
且当前市场状态下的因子证据在至少两个开发折稳定
且至少两个折满足：
    候选组合收益 > 基线组合收益
    候选组合 Sharpe > 基线组合 Sharpe
    换手增量 ≤ 0.20
    最大回撤恶化不超过 5 个百分点
    Beta 增量 ≤ 0.15
→ portfolio_marginal_improvement = true
且当前市场状态下至少两个折也满足同样的组合改善和风险约束
```

任一折缺少足够有效日期、基线或候选组合无法形成，均不能记为“改善”；证据字段缺失时直接
`abstain`，不能用验证期或锁定窗结果补齐。每个候选的逐折输入、基线值、候选值、差值和阈值
都写入证据快照，供调用日志回放。

当前状态证据不足、状态样本不足或任一必要字段缺失时，候选不得放行，系统默认 `abstain`。
整体开发折证据和当前状态证据都必须写入快照，不能用验证期或锁定窗结果补齐。

每 20 日一次的决策只读取冻结的本地历史证据。模型遵循：

```text
observe（观察）：状态、因子证据、相关簇、合法菜单
assess（评估）：相似状态支持度、冗余、缺失与矛盾
decide（决定）：add / drop / replace / abstain，或显式失败
```

LLM 只能从候选菜单中选择合法、稀疏的配方；不能发明公式、改变训练窗口/超参数、改变
股票池、交易成本或覆盖风险规则。证据不足时必须输出 `abstain`（不改变）。

合法配方必须有 5–9 个因子，且至少覆盖趋势、风险、成交量/流动性三类；每个强相关簇
最多一个因子；每个已选因子当日横截面覆盖率至少 95%。单次动作最多 `add=2`、`drop=2`、
`replace=2`。新增或替换必须引用当时已完成的历史证据；同类状态的证据不足时只能
`abstain`。

固定七因子启动配方中已经存在的相关簇成员作为历史基线暂时保留，不因启动而静默修改；
LLM 新增或替换的因子不得制造新的相关簇冲突，后续只能通过显式 `drop/replace` 逐步消除
基线冗余。这一例外只适用于启动配方，不适用于新加入的因子。

每次候选决策最多允许 **4 次** LLM 读取/调用。到达上限仍未产生有效的
`add`、`drop`、`replace` 或 `abstain`，系统记录 `selection_failed`；不得静默延长轮数，
也不得强迫模型作出选择。每次调用（含不消耗试验预算的调用）都写入：调用序号、决策
ID、输入快照哈希、提示词版本、模型输出、是否消耗试验预算、时间戳及读取的证据。审计
必须能够回放完整决策链。

历史语境搜索采用单独的受控通道：默认读取本地
`data/raw/historical_context.jsonl`，也可用有限次数的 Google News RSS 适配器抓取后再
写入该归档。每条记录必须保存发布时间、来源、原文链接、抓取时间和内容哈希，并在加载时
再次过滤 `published_at <= decision_date`。每次决策最多搜索 2 个查询、保留 3 条结果；
搜索结果只提供市场背景，不足以绕过 RankIC、组合边际改善或相关簇约束。网络不可用、来源
时间不明或快照无法保存时，历史语境为空，系统继续按原有证据门槛运行。

### 6.3 S3-next：冠军—挑战者文献检索版本

S3-next 是独立于当前 S3 的**挑战者合同**，不会覆盖 S3 的缓存、调用日志或报告。它保持同一
沪深300、25 个技术因子、20 日标签和 LightGBM 训练方式，但将组合规则改为 `TopK=10,
n_drop=2`，并向 ReAct-lite 提供一个版本化的预置文献索引。

这里的“检索”不是让历史回放访问今天的互联网：索引目前只有代码中手工登记的标题、发布日期、
链接、可支持的因子家族和简短研究含义，**不含论文全文、网页快照或自动抓取语料**。每个决策日
只返回发布时间不晚于该日期、且与当前状态/候选家族相关的少量索引项。任何非 `abstain` 动作
必须在调用日志的 `literature_refs` 中引用其中一个 `source_id`。

文献只用于提出“当前应优先审查趋势、反转、风险、流动性或相对市场哪一类”的研究假设；它不能：

- 新建未注册因子；
- 修改标签、LightGBM、股票池、成本或调仓频率；
- 绕过状态条件的两折组合边际改善门槛；
- 以 2025 以后公开的材料解释或改变过去的决策。

因此 S3-next 的正确解读是“文献辅助的受约束挑战者”，而不是“LLM 自主发现可交易规律”。它若要
升级为新的冠军版本，必须与当前 S3 在相同数据、成本和报告口径下比较，并同时检查超额收益、
回撤、Beta 和换手；一次更高的历史收益不足以升级。

### 6.4 S4：经济意义、高覆盖、低相关的探索型挑战者

S4 是一个**新增探索范围**，不覆盖 S0–S3 或 S3-next，也不把其结果当作 S3 的严格证据。
它允许 LLM 在冻结的 25 个技术因子菜单内，依据确定性市场状态、截至决策日的因子快照和
实时 Crossref 学术索引结果提出挑战配方；但它不再要求候选先通过 S3 的“两折组合边际改善”门槛。

S4-W1 使用独立的周频合同：技术因子每日收盘后更新；标签预测和调仓均为 5 个交易日；
LightGBM 每 20 个交易日重训一次、在中间每周用最新因子重新打分；LLM 配方也每 20 个
交易日从固定七因子重新决策一次。因而模型和 LLM 的慢时钟不会因每周交易而被迫追随短期噪音。
首轮并列两组，除 `n_drop` 外完全一致：`s4` 为 `TopK=10, n_drop=5`，`s4_n2` 为
`TopK=10, n_drop=2`。两组必须共用相同的决策日期、模型、因子配方、成本和数据合同。
尤其是两组共用同一份 LLM 调用日志、证据快照和因子配方缓存；不得因重新调用随机模型而产生
两套不同的配方。

当前 S4 的实际评估窗口限定为 **2024–2025**：2021–2023 仍作为 LightGBM 的成熟训练资料，
但不生成 S4 的 LLM 决策、交易或报告指标。这样可以直接观察验证年与锁定年，同时避免为早期
开发期重复做动态选择。

对每个 `add` 或 `replace`，提示词和代码共同要求：

1. **经济意义**：写明该因子衡量的交易行为或风险，以及为什么它可能与当前状态相关；
2. **高覆盖**：在当日固定七因子可完整计算的可交易股票中，候选因子覆盖率必须不低于 95%；
3. **低相关**：不得与现有或同次新增因子处于同一绝对相关系数不低于 0.80 的相关簇。

LLM 仍不能新造因子、改变股票池、标签、LightGBM、TopK、成本或调仓周期；每次从固定七因子
重新开始，最多变动两个因子，最终仍必须是 5–9 个因子，并保留完整调用日志、输入哈希。S4 会
读取实时索引结果作为可选辅助；若采用则记录引用，网络失败或没有匹配结果均不强迫动作失败。
文献和经济解释只能提出假设，不能构成收益保证。由于实时索引不受历史可得时间限制，S4 是非 PIT
探索，不能用今天的互联网资料支持正式历史结论。

因此 S4 要回答的是“更自由、但仍受覆盖与去冗余约束的 LLM 是否值得作为挑战者继续研究”，而不是
“S4 已经证明能够获利”。若它表现较好，仍需回到同一数据合同下，以 S3 的组合边际证据重新验证。

截至本版，既有 S3 / S3-next 的探索运行**尚未显示稳定、清晰地优于固定因子基线的增量**；这是
“继续寻找更好的动态选择机制”的动机，不是“LLM 无效”的结论。S4 改变了预测、调仓、重训和配方
四个时钟以及 LLM 的动作约束，因此其结果应先按整体挑战者解读，不能把单次升降直接归因给某一个改动。

#### 实时搜索辅助（非 PIT 探索）

S4 保留 S4-W1 的 `H=5, R=5, K=20, J=20`、固定七因子起点、25 个注册技术因子、
经济意义/95%覆盖率/低相关约束和四轮 ReAct 上限；区别是它在每个 LLM 决策日向 Crossref
公开学术索引发起一次有界查询。查询结果会保存为本地 JSON 快照（查询词、返回标题、链接、
抓取时间、哈希或错误），再进入同一次调用的提示词与审计哈希。

这不是 PIT-safe：历史 2022 决策可能读到今天才被索引或更新的资料。它只检验“实时搜索是否能
帮助 LLM 提出更合适的候选配方”，不验证历史可得性，也不得与 S0–S3 的正式 PIT/锁定结论混合。
网络错误返回空列表，不阻断模型；若 LLM 使用了某条实时结果，必须在输出的 `literature_refs`
记录 `source_id`，供后续回放。

## 7. 对照组与时间切分

首轮核心比较有 S0–S3 四组；另设 M0 作为“纯 20 日动量”对照。五组必须共用同一份
数据、成分股、标签、交易与回测合同：

| 编号 | 配方选择方式 |
| --- | --- |
| M0 | 仅使用 `return_20` 的直接横截面排序，不经 LightGBM；用于判断多因子模型是否真的优于纯 20 日动量。 |
| S0 | 固定七因子的技术基线。 |
| S1 | 不使用 LLM：按确定性规则从合法候选配方中选择一个，然后冻结。 |
| S2 | 不使用 LLM：将确定性市场状态映射至预先声明的配方。 |
| S3 | 市场状态 + 受约束的 ReAct-lite 动态选择。 |
| S3-next | 独立的冠军—挑战者版本：S3 的本地证据门槛 + 预置文献索引提示 + `n_drop=2`。 |
| S4-W1-n5 | 周频探索型挑战者：H=5、R=5、K=20、J=20、`n_drop=5`；实时 Crossref 搜索辅助 + 经济意义/当日覆盖率/低相关约束；非 PIT。 |
| S4-W1-n2 | 与 S4-W1-n5 完全相同，只改为 `n_drop=2`，用于隔离组合换手强度。 |

当前代码已经提供统一的 `s0`、`s1`、`s2`、`s3`、`s3_next`、`s4` 与 `s4_n2` profile 运行入口，基础组共用成熟标签、
滚动 LightGBM、TopK/n_drop、开盘成交和收盘估值合同。S3 的真实 LLM 选择器和调用日志
已经接通；在历史证据快照、合法配方动作和失败分支全部通过验收前，S3 结果仍只能视为
工程验证，不能解释为最终的真实 LLM 增量效果。

每次 S0/S1/S2 运行还必须输出两层诊断：第一层是三折和市场状态下的 RankIC/ICIR、
Top/中间/Bottom 分位数的已实现未来超额收益，用于评估分数质量；第二层是相对沪深300
净值、相对回撤、跟踪误差、信息比率与 60 日滚动 Beta，用于评估组合如何转化该分数。

大时间切分冻结为：

- 开发/训练期：2021–2023；其中包含三段按时间顺序排列的折，用于候选证据；
- F1 的评估决策期为 2021-07 至 2021-12，F2 为 2022-07 至 2022-12，F3 为
  2023-07 至 2023-12；任一评估日 `t` 均使用从 2021-01 开始、截至 `t-21` 的成熟样本；
- 验证期：2024；
- 不可触碰的锁定窗：2025。

代码合同中的同一边界为：开发/训练资料从 `2021-01-01` 至 `2023-12-31`，验证资料为
`2024-01-01` 至 `2024-12-31`，锁定测试为 `2025-01-01` 至 `2025-12-31`。这不是新的
时间设计，而是把本节既有设计写入可哈希的 `ProtocolContract`。每次运行同时绑定未复权
OHLCV、历史成分股、公司行动 manifest 及研究源码快照的内容哈希。当前 pipeline 已接通开发/训练、2024
验证和 2025 的机械诊断运行；但三折模型/配方选择、停牌涨跌停可成交证据与锁定窗封存
尚未完成前，2025 仍不得作为正式锁定结论解释。

S1 中，一个配方只有在至少两折的 RankIC 中位数优于基线，且没有违反覆盖度/相关性
限制时才有资格。选择 RankIC 中位数最高者；若并列，先选换手更低者，再选因子更少者。
结果在验证与锁定测试前冻结。三折的精确边界、模型超参数、候选动作上限和交易摩擦
已在本版冻结。每次重训将最近 60 个交易日的成熟训练样本留作内部验证和 early stopping；
F1–F3 的外部评估期永不用于当次训练停止。

S2 对每个市场状态只读取该状态下已完成的开发期证据，按与 S1 相同的 RankIC、换手和
因子数顺序确定一个合法配方；若证据不足，则映射到 S0 的七因子配方。该映射在进入
2024 验证前冻结，因而 S2 是“有状态、无 LLM”的直接对照。

LightGBM 固定项为：`loss=mse`、`learning_rate=0.03`、`feature_fraction=0.80`、
`bagging_fraction=0.80`、`bagging_freq=1`、`num_boost_round=1000`、
`early_stopping_rounds=50`、`seed=20260805`。只在开发期比较以下六个预注册配置：

| 配置 | num_leaves | max_depth | min_data_in_leaf | lambda_l2 |
| --- | ---: | ---: | ---: | ---: |
| M1 | 15 | 4 | 500 | 10 |
| M2 | 15 | 4 | 200 | 1 |
| M3 | 31 | 5 | 500 | 10 |
| M4 | 31 | 5 | 200 | 1 |
| M5 | 63 | 6 | 500 | 10 |
| M6 | 63 | 6 | 200 | 1 |

按三折日度 RankIC 中位数最高者选择；若差距不超过 `0.002`，选 ICIR 更高者；仍并列时，
选叶子更少、`min_data_in_leaf` 更大的较简单模型。选出的单一模型在 S0–S3、2024 与
2025 中共用，不再调参。

### 7.1 参数选择与结果解读授权

M1–M6 只允许在 2021–2023 开发期的三折中比较。选择规则执行完并写入冻结合同后，
不得再根据 2024 或 2025 的收益反向修改参数。2024 是验证期：用于检查冻结后的因子、
模型和执行链是否按预先约定工作；若发现工程错误可以修复并重新开始一个新合同，但不能
为了改善收益调参。2025 是锁定测试：在正式数据档案、公司行动账本、合同哈希和验证期
报告全部封存前，不运行、不查看、不解释其策略优劣。当前使用 `tradability_mode=block`
或存在未封存数据质量问题时，输出只能叫“诊断结果”，不能叫正式验证或锁定结论。

## 8. 评价与报告

主结果是一张跨所选年份连续的净值折线图：每组策略与沪深 300 基准均归一化为 1.0；配套一张
回撤图。连续图必须来自同一条现金、持仓、开盘成交与收盘估值账本，不能把训练、验证或锁定阶段
重新从初始资金运行后拼接。

网页报告的主表按**自然年**（例如 2021、2022、…、2025）列出指标，而不是只列“训练期 / 验证期”。
每一列旁提供由该年策略收益、基准收益、相对差额、夏普与最大回撤生成的简明批注；详细的 LLM
解读以渲染后的 Markdown 显示。自然年表用于解释分段表现，连续图用于判断跨年路径与回撤，两者都
不能替代对未触碰窗口和数据质量边界的审查。

主表包含：年化净收益、相对基准的超额收益、夏普比率、最大回撤、年化波动率、换手率、
交易成本、平均持仓数、RankIC/ICIR、因子覆盖度、未成交订单数与公司行动失败数。初始
资金为 100 万元，买入按 100 股整数手，零头保留现金。假设开盘成交但无法从日线完整
识别涨跌停排队，该潜在乐观偏差必须在报告中披露。Alpha、Beta、Sortino、信息比率等
是附录诊断指标，不是单一成功标准。

首轮交易成本为：假设全包券商佣金（含交易规费）双向各 3bp，过户费双向各 0.1bp，
卖出印花税 5bp，滑点双向各 5bp；因此买入 8.1bp、卖出 13.1bp、往返约 21.2bp。
佣金与滑点是研究假设；法规费用必须在运行清单中附当时来源和版本。不得再将已包含在
全包佣金内的交易规费重复相加。当前来源为[国家税务总局印花税公告](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5211343/content.html)
和[上交所投资者交易费用说明](https://one.sse.com.cn/onething/gptz/)；运行时仍须记录实际查询日期。

执行使用未复权开盘价，因子价格口径必须写入清单。正式路径的现金/持仓账本在开盘将
目标权重换算为 100 股整数手，先卖后买，零头保留为现金，收盘按持仓估值。已识别且具有
完整日期证据的送转股调整股数，现金分红在付款日进入现金；无法得到整数股、付款日期
矛盾或公司行动在除权日后才公告时，运行显式失败。配股、停牌重组或未覆盖的持仓公司
行动同样不能静默近似。因子所需窗口缺失则股票当日不合格；目标订单的开盘价缺失或无效
时整次运行失败；持仓收盘价缺失或无效时整次运行失败。不对因子、成交价或估值价使用
前向填充。AKShare 当前日线没有可审计的历史停牌/涨跌停可成交标记，因此不能把该项
简化为“日线价格存在即一定成交”；当前已从独立的 JoinQuant 导出接入这些字段，但该导出
仍有 386 个历史沪深300生效区间的字段不完整日，详见 `data/raw/tradability_joinquant/
manifests/tradability_coverage.json`。本阶段暂不追补这些日期，正式锁定测试不把缺失状态
猜成停牌或涨跌停；如果只做因子/模型诊断，可显式使用 `tradability_mode=block`，
将相关订单保守阻断并记录为 `blocked_missing_tradability`。这种诊断结果不授权正式验证
或锁定窗结论；研究状态仍为相对 PIT、非完全严格 PIT。

行情缺失先由 `mystock data repair-missing` 自动重抓；仍为空时，诊断运行将股票/订单隔离，
并在运行质量状态中标记 `complete_with_quarantines`，不影响其他股票继续计算。

基准初始使用沪深 300价格指数 `000300.SH`，报告明确其为价格口径。只有当组合账本已
完整计入现金分红后，才可改用同口径的沪深 300全收益指数；在此之前，Alpha、Beta 与
超额收益仅为诊断，不能作为主要结论。

LLM 使用 OpenAI-compatible 接口，密钥只存放在本地 `.env`。当前候选供应商信息来自
本地既有配置和运行界面；`LLM_API_BASE_URL` 必须配置到 API 的 `/v1` 根路径，而不是
完整的 `/v1/chat/completions` 路径，模型 ID 同样由 `.env` 提供并写入运行清单。密钥、
端点和模型在代码中均不得硬编码。

不能仅因总收益更高就接受一个结果；还必须结合成本、回撤、换手、数据覆盖与未触碰的
2025 结果解释。正向结果最强的反方解释是：它可能过度拟合 2021–2024 的设计选择。
锁定窗与回放日志是直接防护，而不是收益保证。

## 9. 当前范围之外

- 所有数据类型的完全严格 PIT；
- 实时自动交易；
- 新闻抓取 Agent 与新闻 alpha；
- 基本面因子实现；
- 组合优化 / 风险预算优化；
- 全 A 股大股票池研究；
- 由 LLM 决定因子公式、模型窗口或交易成本。

这些均为暂存扩展。只有技术基线与动态配方对比可端到端复现后，才可提升优先级。
