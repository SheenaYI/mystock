# "一夜持股法" 模拟观测平台 v2 重设计 — 信息架构与视觉重做

日期：2026-07-24

## 背景

v1（`docs/superpowers/specs/2026-07-24-overnight-holding-simulator-design.md`，已发布为 Artifact）上线后用户反馈：作为投资者，无法清楚看到整体收益情况，也无法判断该策略是否能满足未来一段时间的收益预期；界面信息全部纵向堆叠、没有分类，视觉设计（圆角卡片、按钮风格）不够"金融工具"感。

用户明确表示**不反对底层引擎逻辑**（选股算法、买入价位模拟、次日走势模拟、卖出规则、状态机）——这些已在 `sim-engine.mjs` 中完整实现并有 31 个单元测试覆盖。本次是**UI/信息架构层面的重做**，唯一涉及行为的改动是"今日决策"里的手动买入勾选（见下）。

## 范围

- **不改动**：`sim-engine.mjs` 中已测试的选股打分算法、次日模拟、卖出规则判定、`createInitialState`/`resetSimulation`/`updateStrategyParams`。
- **改动**：整个 UI 层（`overnight-holding-simulator.html`），从单页纵向堆叠改为 4 个标签页；新增"策略表现"统计与外推估算；新增手动勾选买入的决策环节。
- **唯一的行为变化**：买入不再由系统自动选定分数最高的 N 只，而是用户在推荐卡片上勾选后确认（详见"今日决策"一节的技术方案）。

## 信息架构：4 个标签页

顶部标签导航（替代现在的纵向堆叠 + 侧边固定面板）：

**今日决策 → 持仓与收益 → 策略表现 → 策略设置**

切换标签不触发任何状态变更，纯视图切换；`AppState` 全局共享，任一标签的操作（买入、结算、改设置、重置）后其他标签下次打开时自动反映最新数据。

## 一、今日决策 Tab

这是默认打开的首页，回答"我今天该做什么"。

**顶部**：`第 N 天` + 当前阶段状态 pill（`待选股` / `持仓中，待结算` / `刚结算`）。

**核心区域，按阶段切换内容：**

1. **待选股**：按钮"生成今日推荐"。点击后调用 `selectDailyPicks(pool, params, rng, 3)`（引擎既有函数，不改）获得最多 3 个候选，渲染为 3 张卡片：股票名/行业、建议买入价区间（`computeBuyPriceRange`）、匹配度得分、推荐理由列表。**每张卡片带一个勾选框**，默认勾中得分最高的 `strategyParams.maxHoldings` 张（保留原有默认行为作为初始建议），用户可自由增减勾选（含全不选 = 今日不买，或全选 = 3 只都买，不再受 `maxHoldings` 硬性上限约束——该参数现在只决定"默认预选几只"，不再是买入上限）。确认后点击"确认买入"。

   **技术方案（不改引擎，只改 UI 编排）**：`generateDailyPicks` 步骤只调用 `selectDailyPicks`，结果存入一个 UI 层专属的 `pendingPicks` 字段（不写入引擎 `State`，不进入 `localStorage` 的核心状态，只是页面临时变量），不触发 `runSelectionPhase`。用户勾选变化只更新本地勾选集合。点击"确认买入"时，取用户勾选的子集 `selectedPicks`，调用既有 `computePositions(selectedPicks, state.capital, {...state.strategyParams, maxHoldings: selectedPicks.length})` 得到 positions，然后手动应用与 `runSelectionPhase` 内部相同的状态更新（`phase: 'holding'`、`positions`、`lastPicks: selectedPicks`、`capital -= 投入总额`），而不是调用 `runSelectionPhase` 本身（因为该函数内部会用引擎自己的 top-N 逻辑重新圈定购买对象，不接受外部指定的子集）。`selectedPicks` 为空数组时同样有效（今日不买），复用 `computePositions([], ...)` 已验证的空输入行为（返回 `[]`，不抛错）。

2. **持仓中，待结算**：只读展示当前持仓（复用 v1 的持仓卡片样式），提示"次日开盘后回来结算"，按钮"推进到次日结算"（调用既有 `runSettlementPhase`，不变）。

3. **刚结算**：展示本次结算结果（复用 v1 的结算卡片：止盈/止损/平仓离场标签 + 盈亏），按钮"知道了 → 生成明日推荐"清空 `lastSettlement` 并回到状态 1。

## 二、持仓与收益 Tab

- **顶部大数字区（4 个并排指标卡）**：总资产、累计盈亏（¥ 与 % 并显，相对 `initialCapital`）、最近一轮盈亏（取 `history` 最后一条的 `totalPnlAmount`；`history` 为空时显示 `--`）、当前持仓数。数字统一等宽字体，涨用红、跌用绿（对齐 A 股习惯）。
- **资金曲线图**：在此页面放大展示（沿用 v1 的 SVG 折线图实现，仅调整尺寸和位置，不改算法）。
- **当前持仓明细表**：持仓中才显示；字段同"今日决策"里的持仓卡片，改为表格形式（股票、行业、买入价、股数、成本）。
- **交易记录表**：沿用 v1 的历史记录表（按天、含行业、盈亏、胜率），移到本页作为收益的完整佐证。

## 三、策略表现 Tab（新增）

专门回答"这个策略是否可能满足我未来一段时间的收益预期"：

- **胜率**：`sum(day.winCount) / sum(day.results.length)`，跨所有历史天数。
- **平均单笔收益率**：对历史中所有 `results[].pnlPct`（每只股票每次交易的收益率，而非按天聚合）取平均。
- **最大回撤**：基于资金曲线（`initialCapital` + 各天 `capitalAfter` 序列）计算 `max((历史最高点 - 当前点) / 历史最高点)`。
- **年化收益率外推**：`(当前总资产 / 初始资金) ^ (252 / 已完成天数) - 1`，按 252 个交易日/年折算。历史不足 3 天时显示"数据不足，继续模拟几天后查看"而不是给出误导性数字。数字下方固定标注一行小字："仅为历史表现外推估算，不代表未来收益，不构成投资建议。"

不在本轮范围内（记录为后续可能的迭代，这次不做）：多组参数快照对比、蒙特卡洛式区间估计。

## 四、策略设置 Tab

与 v1 内容一致（初始资金、八项选股条件阈值、仓位/止盈止损参数、重置模拟按钮），只是从"纵向堆叠中的一块"变成独立标签页，视觉上按下面的新风格重做。

## 视觉设计方向

从"消费级 App 风格"（大圆角卡片、粗描边按钮）转向更克制的"金融工具"风格：

- 圆角从现在的 10–12px 收紧到 4px 左右，减少视觉柔软感
- 金额、百分比等数字统一使用等宽数字（`font-variant-numeric: tabular-nums`），右对齐，便于扫读比对
- 红涨绿跌只用于数据本身（数字颜色、涨跌箭头），不用于装饰性背景色块
- 顶部标签导航替代纵向堆叠 + 侧边设置面板；标签栏样式简洁（文字 + 底部下划线指示当前项，不用圆角"药丸"按钮）
- 保持深色/浅色模式自适应（沿用 v1 的 `prefers-color-scheme` 方案）

## 不变的部分（复用 v1 已验证代码）

- `sim-engine.mjs` 全部内容（含其在 HTML 中的内联副本）
- `localStorage` 持久化机制（`saveState`/`loadState`），核心 `AppState` 结构不变，只是新增一个 UI 专属、不持久化的 `pendingPicks`/勾选集合
- 资金曲线 SVG 绘制逻辑、历史记录表数据来源（`AppState.history`）
